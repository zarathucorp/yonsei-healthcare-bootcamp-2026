1. 파일 역할- global.R과 analysis.R

별도의 두 파일로 구분하여 작성한다.
global.R에서 분석 전에 분석에 필요한 데이터와 객체를 만들어 준비하는 파일이고
analysis.R에서 실제 분석을 수행한다.

global.R

  • 패키지 불러오기
  • 데이터 읽기와 전처리
  • 파생변수 생성

analysis.R

  • 통계분석 실행

  • 분석 결과 검증

1.1 - global.R의 기본 흐름

분석에 사용할 데이터와 변수를 미리 준비하는 파일이다.

library(data.table)
library(magrittr)
library(jstable)

# 1. 데이터 불러오기 
a <- fread("synthetic_data.csv")

# 2. 전처리와 파생변수
a[, Age60 := factor(
  ifelse(Age < 60, "<60", "≥60")
)]

# 3. 분석 변수 목록
varlist <- list(
  Time  = "primary_time_mo",
  Event = "primary_event",
  Base  = c("group", "Age", "Sex", "BMI")
)

# 4. 분석용 데이터 만들기
out <- a[, .SD, .SDcols = unique(unlist(varlist))]

# 5. 표시용 라벨 만들기
out.label <- jstable::mk.lev(out)

실행 순서

  1. 데이터를 읽는다.
  2. 필요한 파생변수를 만든다.
  3. 사용할 변수를 varlist에 정리한다.
  4. out을 만들고 자료형을 지정한다.
  5. out.label을 만듭니다.

1.2 - analysis.R의 기본 흐름

global.R에서 준비한 out을 그대로 사용해 분석하고, 표와 그림을 모아 저장하는 파일이다.

source("global.R")

ft_list <- list()
plot_list <- list()

# 1. 통계분석 실행
fit <- survival::coxph(
  survival::Surv(primary_time_mo, primary_event) ~ group,
  data = out
)

# 2. 표 결과 모으기
ft_list[["Cox model"]] <-
  summary(fit)$coefficients %>%
  data.table(keep.rownames = "Variable")

# 3. 그림 결과 모으기
km_fit <- survival::survfit(
  survival::Surv(primary_time_mo, primary_event) ~ group,
  data = out
)
plot_list[["KM curve"]] <-
  jskm::jskm(km_fit, data = out)

# 4. 산출물 저장
openxlsx::write.xlsx(
  ft_list, "results/Tables.xlsx"
)

실행 순서

  1. global.R을 불러온다.
  2. out으로 통계분석을 실행한다.
  3. 표와 그림을 목록에 모은다.
  4. 표는 Excel, 그림은 PPT로 저장한다.
  5. 저장된 파일과 주요 수치를 확인한다.

2. 변수 관리 - varlist와 out

varlist <- list(
  ID       = "ID",
  Base     = c("group", "Age", "Sex", "BMI"),
  Followup = "admend_mo",
  Time     = "primary_time_mo",

out <- a[, .SD,
         .SDcols = unique(unlist(varlist))]

stopifnot(
  identical(varlist$Time, "primary_time_mo"),
  identical(varlist$Event, "primary_event")
)

out과 out.label은 global.R에서 만든다.
analysis.R에서 out과 out.label을 그대로 사용한다.

varlist는 분석에 사용할 변수의 이름을 정리한 목록이다.
out은 varlist에 저장된 변수명을 기준으로 원자료에서 추출한 실제 분석 데이터다.

생존분석을 할 경우 varlist$Event, varlist$Time에 event/time 변수를 순서에 맞춰 저장한다.

반복측정데이터일 때는 out 기반으로 long form out.long을 추가로 만들고 out과 동일하게 작업한다.

varlist와 out이 나오기 전에 필요한 파생변수를 모두 만든다.
out 이후에는 새 분석용 변수를 만들지 않는다.

out을 만들고 factor/numeric을 지정한 뒤, out.label을 만든다.
out.label은 사람이 읽기 쉽게 만든 표시용 라벨 데이터이다.

2.2 - 일반적인 변수 관리

일반적인 변수 관리 규칙

  • factor/numeric 변환: 각 변수를 분석 목적에 맞게 자료형을 지정하는 작업
    ex) factor: 성별, 치료군 같은 범주형 변수
    numeric: 나이, 체중 같은 연속형 변수

  • 같은 그룹명/변수명 반복 표기하지 않는다.

  • 컬럼명/변수명 그대로 노출하지 않는다.
    ex) dose_mg, ANC_bl, var123

  • 병합한 컬럼에는 valign(j = ..., valign = "top")과 align(j = ..., align = "left")를 적용한다.

  • 라벨은 named character vector, jstable::mk.lev(), out.label을 활용한다.

부등호/특수문자 표기

  • 테이블, 그림, 라벨 등 사용자에게 보이는 텍스트에서 >=는 ≥, <=는 ≤로 표기한다.

  • R 코드 문자열에서도 동일하게 쓴다. (단, 코드 로직 조건문의 >=, <=는 R 문법이므로 그대로 유지한다.) ex) labels = c("≥35") 또는 labels = c("\u226535")

  • kg/m^2는 kg/m²로 표기한다. 범위 하이픈은 en dash(–) 사용을 고려한다.

  • \uXXXX 유니코드 이스케이프는 백틱 안에서 사용할 수 없다.

  • 한글/특수문자가 포함된 컬럼명은 setnames()로 영문명으로 바꾼 뒤 사용한다.

  • 리스트 이름에 특수문자가 필요하면 setNames() 또는 [[ ]] 할당을 사용한다.

2.3 - 0/1 factor level

factor_vars <- names(out)[vapply(
  out,
  function(x) length(unique(na.omit(x))) <= 6L,
  logical(1)
)]

vars01 <- vapply(factor_vars, function(v) {
  lv <- sort(unique(na.omit(as.character(out[[v]]))))
  length(lv) > 0L && all(lv %in% c("0", "1"))
}, logical(1))

for (v in names(vars01)[vars01]) {
  out[, (v) := factor(
    as.character(get(v)),
    levels = c("0", "1")
  )]
}

한쪽 값만 관측된 0/1 변수도 두 범주가 표에 표시되도록 levels = c(“0”, “1”)로 고정한다.

out.label의 값 라벨을 수정하여 0/1을 No/Yes처럼 의미 있는 표현으로 표시한다.

관측되지 않은 범주도 표에 표시할 수 있도록 factor level을 미리 고정한다.

factor(x, levels = c("0", "1"))

3 - 분석 기준

표와 그림 관리

  • 표는 목록에 모은 뒤 하나의 Excel 파일에 여러 시트로 저장한다.
  • 그림은 lapply로 생성하여 plot_list에 먼저 저장한다.

스크립트 구성

  • 분석 순서가 위에서 아래로 드러나도록 작성한다.
  • 반복해서 사용하지 않는 코드는 불필요하게 함수로 감싸지 않는다.
  • 데이터 준비, 분석, 표·그림 생성, 파일 저장, 결과 검증 순서를 유지한다.
  • 하나의 분석 과정에서 일관된 문법으로 작성하여 코드의 흐름을 빠르게 파악하고 오류를 찾기 쉽게 한다.

3.3 - 분석 코드 주의사항

jskm은 p-value와 risk table을 계산하기 위해 원본 데이터와 formula를 다시 확인하여 사용한다.

데이터 명시

data = dd를 명시하여 survfit()과 jskm()이 같은 데이터를 사용하도록 한다.

fit <- survfit(
    Surv(time, event) ~ group,
    data = dd
  )

  jskm(
    fit,
    data = dd,
    pval = TRUE
  )

survfit(fmla, data = dd)로 작성하면 jskm이 시간, 사건, 비교군 변수를 확인하지 못할 수 있다.

문제를 해결한다.

3.5 - forest plot

df$Variable <- ifelse(is.na(df$Count), df$Variable, paste0("   ", df$Variable))
df$Count <- ifelse(is.na(df$Count), "", df$Count)
df$` ` <- paste(rep(" ", 20), collapse = " ")
df$`OR (95% CI)` <- ifelse(is.na(df$est), "",
                            sprintf("%.2f (%.2f-%.2f)", df$est, df$low, df$high))
df[is.na(`P value`), `P value` := ""]

p <- forest(
  df[, c("Variable", "Count", " ", "OR (95% CI)", "P value", "P interaction")],
  est = df$est, lower = df$low, upper = df$high,
  sizes = 0.4, ci_column = 3, ref_line = 1,
  x_trans = "log", xlim = c(0.1, 10), ticks_at = c(0.25, 0.5, 1, 2, 4),
  theme = forest_theme(base_size = 10, refline_gp = gpar(col = "grey50"))
)
df[, Event := paste0(Events, "/", N, " (", sprintf("%.1f", Events / N * 100), "%)")]
  • TableSubgroupMultiCox/GLM() 결과는 data.frame에서 data.table로 변환한 뒤 :=를 사용한다.
  • forest()에 넘기는 data.frame은 표시할 열만 선택한다.
  • forest_theme()에서는 refline_gp = gpar(col = ...), footnote_gp = gpar(col = ...)를 사용한다.
  • refline_col, footnote_col은 쓰지 않는다. library(grid)를 사용한다.

Forest plot 레이아웃과 시각요소

  • CI를 그리는 열은 빈 공백 열로 확보하여 선이 글자와 겹치지 않도록 한다.
  • sizes에는 스칼라를 넣어 모든 점의 크기를 동일하게 둔다. ex) sizes = 0.4
  • x_trans = "log"로 x축 로그 스케일을 사용한다.
  • 극단값(OR > 100 또는 Inf)은 est, low, high를 NA로 설정해서 점과 선을 그리지 않는다.
  • 극단값 행의 p-value도 빈칸으로 둔다.
  • 서브그룹 하위 레벨은 들여쓴다. ex) df$Variable <- ifelse(is.na(df$Count), df$Variable, paste0(" ", df$Variable))
  • Count, P value 등 표시용 컬럼의 NA는 ""로 변환한 뒤 forest()에 전달한다.
  • Event는 Events/N (%) 형식으로 표시한다.
  • header row의 P value는 ""로 처리한다.
  • level 라벨은 0/1 대신 No/Yes 등 의미 있는 라벨로 변환한다.

4. 산출물 기준 - 그림

심장학 연구 KM curve

  • cumhaz = TRUE를 사용하여 cumulative incidence, 즉 1-S(t) 형태로 표시한다.

  • 모든 글자는 한 페이지 안에 배치한다.
  • 글자 자림과 화면 밖 넘침 방지한다.
  • 그림, 도형, 화살표가 글자를 가리지 않도록 배치한다.

  • 부자연스러운 수동태, “~에 대해”, “~를 가진다” 식 직역을 피한다.
  • “권합니다”, “권장합니다”, “권고합니다”, “권장” 표현은 쓰지 않는다. 대신 “~하는 게 좋겠습니다”로 쓴다.
